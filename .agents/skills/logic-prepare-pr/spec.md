# Acceptance scenarios

Given an Operator diff changing a CRD and generated manifests, draft a title and body identifying API impact and the generation check. Explain any required migration even when it needs several sentences. Omit the inventory of generated files. If KIND tests were skipped, the draft must say so.

Given a Console PR with a launcher-only fix and an unrelated unstaged UI change, describe only the branch diff in the PR. Flag the unstaged change separately.

Given a request only to explain a workflow, leave this skill inactive. For client qualification, replay the same fixture with and without the skill, record client/model and revision, and have a reviewer compare factual accuracy and usefulness.

Given a PR request without an issue, ask for one or for confirmation to create one. For a partial product PR addressing kubesmarts/logic-agents#1, include Refs: kubesmarts/logic-agents#1, answers explaining the problem, the outcome and actual verification evidence.
